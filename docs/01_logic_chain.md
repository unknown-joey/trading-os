# 01. 从交易问题出发的逻辑链条

## 总原则

这套系统不是从“我要预测什么”开始。

它从真实交易会遇到的问题开始：

```text
入场：我现在能不能开第一笔？
加仓：行情对了以后，我能不能加？
止损：如果错了，我最多亏多少？
止盈：如果对了，我怎么把风险变小，同时尽量拿住？
风控：账户整体有没有暴露过大？
复盘：规则有没有被破坏？
```

量化在这里不是发动机。

量化是仪表盘：

```text
它不替你相信某个行情。
它只告诉你风险、仓位、状态、触发条件。
```

## 一句话主线

```text
先判断能不能入场；
入场后只允许小风险试错；
行情证明自己后才允许加仓；
每次加仓都重新计算止损风险；
盈利到 2R 后推保本；
最后用总仓位、相关性、节假日规则防止账户整体出事。
```

仓位管理先按市场和仓位类型分层：

```text
市场：股票、期货
仓位类型：老仓、新仓、网格仓
```

每一种仓位类型都先回答：

```text
入场/建仓逻辑是什么？
最大资金占比或仓位限制是什么？
风险控制方式是什么？
止盈或退出规则是什么？
```

当前阶段先整理仓位管理规则，不加入市场状态判断。

## 0. 入场前：先问能不能碰

入场前先不问会不会涨。

先问：

```text
这个品种我能不能承受？
这个品种和已有持仓是不是同一个风险？
现在账户还有没有风险额度？
现在是不是节假日或重大风险窗口？
```

量化在这里做四件事：

```text
计算一手名义价值。
计算一手极端亏损。
检查同组相关性。
检查账户剩余仓位和剩余风险额度。
```

通过条件：

```text
一手极端亏损可承受。
不是强相关重复下注。
账户总仓位没有超限。
不是风险事件模式。
```

不通过动作：

```text
不入场。
或者换更小合约。
或者降低已有仓位。
或者等风险窗口过去。
```

## 1. 入场：第一笔怎么开

入场分成两类。

第一类是低位网格入场：

```text
用于历史低位。
不赌立刻上涨。
用极轻仓等待均值回归。
重点是压力测试，而不是预测。
```

第二类是趋势试错入场：

```text
用于突破或趋势确认。
必须带止损。
每笔最大亏损不超过账户 1%。
仓位由止损距离反推。
```

量化在入场环节解决的问题：

```text
低位网格：如果继续跌 10%、20%、30%、50%，账户会怎样？
趋势试错：如果触发止损，这笔亏多少钱？
```

入场决策：

```text
低位但压力测试扛不住 → 不开网格。
趋势但止损风险超过 1% → 减仓或不做。
看不懂 → 不入场。
```

## 2. 加仓：什么时候允许把仓位加大

加仓不是因为“我更有信心”。

加仓只因为：

```text
行情已经证明前一笔是对的。
账户还有风险额度。
新增仓位的止损风险可控。
总仓位没有超限。
```

每一次加仓都当成一笔新交易。

量化在加仓环节解决的问题：

```text
新增仓位开多少手？
新增仓位止损在哪里？
新增仓位如果错了亏多少？
新增后账户总仓位是多少？
新增后未保本风险是多少？
```

加仓通过条件：

```text
单笔新增风险 ≤ 账户 1%。
总名义仓位 ≤ 平时 50%。
节假日前总名义仓位 ≤ 25%。
强相关风险没有重复堆积。
```

不通过动作：

```text
减少加仓手数。
拉近止损但不能乱设。
等待前一笔推保本后再加。
直接放弃这次加仓。
```

## 3. 止损：错了以后怎么处理

止损不是情绪决定。

止损在入场前就要确定。

趋势仓的规则：

```text
开仓前确定止损价。
用止损距离计算手数。
触发止损就退出。
不因为底仓盈利而放松新仓止损。
```

网格仓的规则：

```text
网格可以不设普通止损。
但必须提前通过极端压力测试。
如果补仓路径会拖死账户，就不能开。
```

量化在止损环节解决的问题：

```text
趋势仓：当前是否触发止损？
趋势仓：触发止损后亏损是否在计划内？
网格仓：继续下跌时是否突破账户承受能力？
组合层面：多个品种同时下跌时账户会不会失控？
```

止损动作：

```text
趋势仓触发止损 → 退出。
网格压力失控 → 停止补仓或提前降风险。
组合风险超限 → 先处理账户风险，而不是争论单个品种。
```

## 4. 止盈：赚了以后怎么处理

这里的重点不是“赶紧卖掉”。

重点是：

```text
先把风险降下来。
再让利润继续跑。
```

核心规则：

```text
盈利达到 2R。
止损抬到开仓价。
这笔仓从风险仓变成保本仓。
释放风险额度。
可以考虑下一笔加仓。
```

量化在止盈环节解决的问题：

```text
当前盈利是多少 R？
是否已经达到 2R？
哪笔仓应该推保本？
推保本后释放多少风险额度？
是否允许开下一笔？
```

止盈动作：

```text
没到 2R → 不动。
到 2R → 推保本。
推保本后 → 老仓继续持有，新仓重新按 1% 风险试错。
趋势结束 → 根据后续规则退出。
```

## 5. 总风控：防止账户整体出事

单笔交易没问题，不代表账户没问题。

账户层面的风险包括：

```text
总仓位过高。
多个品种强相关。
节假日前仓位太重。
流动性突然消失。
跳空或连续跌停。
网格同时补仓。
```

量化在总风控环节解决的问题：

```text
当前总名义仓位是多少？
当前未保本风险是多少？
当前各风险组暴露是多少？
节假日前是否超过 25%？
如果所有持仓同时极端波动，账户剩多少？
```

总风控动作：

```text
总仓位超限 → 不开新仓，先降仓。
强相关重复 → 只保留一个代表品种。
节假日前超限 → 主动降到 25% 内。
风险事件模式 → 暂停网格补仓和趋势加仓。
```

## 6. 复盘：检查规则是否被破坏

复盘不是为了证明自己聪明。

复盘只检查：

```text
有没有跳过入场前检查？
有没有在风险超限时开仓？
有没有加仓不设止损？
有没有亏损超过计划？
有没有到了 2R 但没推保本？
有没有强相关重复下注？
有没有节假日前没降仓？
```

量化在复盘环节解决的问题：

```text
自动记录每笔交易的计划风险。
自动记录实际亏损和实际盈利 R。
自动标记规则违规。
统计哪些错误最常出现。
```

复盘动作：

```text
规则有效但执行错 → 改执行流程。
规则本身不清楚 → 改规则定义。
规则无法量化检查 → 暂时不要自动交易，只做人工确认。
```

## 最终顺序

每天只按这个顺序看：

```text
1. 入场前：这个品种和账户现在能不能碰？
2. 入场：如果开第一笔，错了亏多少？
3. 加仓：如果加一笔，新增风险是多少？
4. 止损：有没有触发退出或停止补仓？
5. 止盈：有没有达到 2R，需要推保本？
6. 总风控：账户整体有没有超限？
7. 复盘：有没有规则被破坏？
```
