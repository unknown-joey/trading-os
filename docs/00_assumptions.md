# 00. 系统前提和边界

## 这套系统不做什么

它不追求预测明天涨跌。

它不寻找永远有效的因子。

它不把技术形态当成核心信仰。

它不允许因为“看起来机会很大”而跳过风控。

## 这套系统做什么

它只解决四个问题：

```text
第一，猜错了怎么不死。
第二，猜对了怎么尽量拿住。
第三，仓位什么时候可以加。
第四，盈利后怎么把风险锁回去。
```

## 基本假设

```text
账户资金：由 config/assumptions.json 设置。
平时总仓位上限：默认 50%。
节假日总仓位上限：默认 25%。
趋势单笔风险上限：默认账户资金的 1%。
保本推进条件：盈利达到 2R。
强相关品种：同一风险组默认只保留一个主交易对象。
极端价格：先用人工假设，后续可以接入历史极值或压力测试模型。
```

仓位管理规则单独放在：

```text
docs/03_position_management_rules.md
config/position_management_rules.json
```

当前只整理仓位管理规则结构，不实现市场状态识别。

## 关于“可去杠杆”

交易所保证金不是你的真实风险。

真实风险要按极端情况估计：

```text
一手极端亏损 = abs(当前价格 - 极端价格) * 合约乘数
```

如果一手极端亏损已经超过账户可承受范围，这个品种就不应该进入候选池。

## 关于“网格不止损”

网格不止损不是无限扛。

它必须同时满足：

```text
历史低位
轻仓
多品种
不强相关
极端下跌能承受
```

如果网格压力测试无法证明“跌很多也不会拖死账户”，就不应该开。

## 关于“趋势加仓”

趋势加仓每一笔都当成新交易。

底仓盈利不代表新仓可以乱开。

每笔趋势仓都要回答：

```text
开仓价是多少？
止损价是多少？
如果错了亏多少？
是否小于账户资金的 1%？
是否超过总仓位上限？
```

## 关于“保本推进”

趋势仓盈利到 2R 后，止损抬到开仓价。

这笔仓位从“有风险仓”变成“保本仓”。

它释放风险额度，但不代表它真的没有滑点风险。

现实交易里仍然要考虑跳空、跌停、流动性消失。
