# Trading OS｜守仓

> 纪律大于预测。帮助交易者执行自己的规则，而不是告诉用户怎么买。

Trading OS 是一个面向个人投资者的开源持仓风险看板。它把账户资金、持仓、止损价和用户自定义规则放到同一个页面，回答三个问题：账户是否安全、风险用到了哪里、现在是否还能增加风险。

它不是选股软件，不预测涨跌，不提供喊单，也不会自动下单。

## 当前版本

当前处于 **V0 风险看板**，重点是把日常持仓管理做清楚：

- 账户总资产拆分为现金余额与持仓市值
- 新增、修改、减仓和清仓
- 减仓时按成交价自动回补现金；也可按券商余额手工校准
- 配置单笔风险、总仓位、节假日仓位等纪律规则
- 一键刷新 A 股和 ETF 公开行情
- 检查总仓位、单品种风险和集中度，并说明触发原因
- 所有数据默认保存在运行这套程序的设备上

计算器、加仓规划、交易日志和 AI 总结暂不放进当前界面。先让风险看板稳定、清晰、可日常使用，再逐步恢复。

## 页面结构

```text
Trading OS（首页）
├── 账户概览：现金、持仓市值、风险利用率
├── 持仓概览：品种、数量、成本价、当前价、风控价
├── 今日纪律：规则是否被违反
└── 风险提醒：结论、原因、对应规则和建议动作

持仓管理：新增、修改、减仓、清仓、刷新行情
规则设置：账户资金、现金余额、风险预算和仓位上限
风险复盘：用当前持仓和规则解释风险
```

## 快速开始

需要 Python 3.10 或更高版本。

```bash
git clone https://github.com/unknown-joey/trading-os.git
cd trading-os
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python3 -m pip install -r requirements.txt
streamlit run src/web_app.py
```

浏览器打开终端显示的地址，通常是 `http://localhost:8501`。

首次启动会使用公开的演示数据。请在“持仓管理”和“规则设置”中替换成自己的数据。不要把填写过真实账户信息的 `data/` 和 `config/assumptions.json` 提交到公开仓库。

## 行情说明

行情通过 [AKShare](https://github.com/akfamily/akshare) 聚合的公开数据接口获取，仅用于更新持仓当前价和风险计算：

- 属于准实时公开行情，不是券商级逐笔行情
- 页面会显示来源和最近更新时间
- 获取失败时保留原价格，不用空值覆盖持仓
- 用户始终可以手工修正价格

公开行情接口可能随上游变更而暂时失效。本项目不保证行情完整性或时效性，交易前请以持牌券商数据为准。

## 数据与隐私

个人账户数据不应进入 GitHub。本仓库只提供演示数据和程序代码：

| 数据 | 默认位置 | 是否建议提交 |
|---|---|---|
| 持仓 | `data/stock_positions.csv` | 否 |
| 现金和账户规则 | `config/assumptions.json` | 否，公开仓库仅保留示例 |
| 行情更新时间 | `data/market_data_status.json` | 否 |
| 产品规则说明 | `PRODUCT.md` | 是 |

如果部署到公网，当前单机版不适合多人共用：文件存储没有用户隔离和账号系统。个人使用建议把网页设为私有访问；多人版本应改为带登录和数据库隔离的服务。

## 部署成“随开随用”的网页

最省成本的个人方案是部署到支持 Streamlit 的托管平台，并把仓库设为公开、应用设为私有（如果平台支持）。部署入口是：

```text
src/web_app.py
```

需要注意：免费托管服务可能休眠；重新打开时会自动唤醒。部分平台的临时磁盘会在重启后丢失页面里修改的数据，因此长期使用前应接入 SQLite/PostgreSQL 等持久化数据库，或定期备份本地数据文件。

## 开发约定

1. 开发前完整阅读 `PRODUCT.md`。
2. 建议必须包含结论、数据原因、触发规则和下一步动作。
3. 不增加行情预测、自动交易或无法解释的 AI 建议。
4. 修改计算逻辑后，同时验证持仓、现金、规则和复盘的数据链。
5. 不提交真实持仓、手机号、密钥、Cookie 或部署凭证。

欢迎提交 Issue 和 Pull Request。较大的功能变更请先说明它解决的纪律问题，以及是否符合当前版本范围。
